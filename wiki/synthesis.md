# Synthesis

RALPH should be optimized for research leverage, not for premature execution.

The core bet is that Tomas needs a system that continuously surfaces high-value unknowns, turns them into candidates, validates them with evidence, and records decisions. The trading-system map is useful, but only as a capability map. The correct order is:

1. Build memory and source discipline.
2. Run collection and discovery loops.
3. Turn repeated signals into candidates.
4. Validate candidates with benchmarks or replay experiments.
5. Decide: investigate, prototype, watch, discard, or defer.
6. Only later choose framework rails.

> Synthesis: RALPH becomes useful when it can say "this is worth your attention" and "this is not worth building" with citations, not when it can run code autonomously.

After source-backed review, the first design correction is clear: RALPH must run Source Intake before designing more loops. Without raw sources, source pages, and an index, automation would only amplify assumptions.

The second correction is that "trading bot system" is not yet a spec. It is an unknown. RALPH must discover and compare strategies first, then let architecture emerge from the chosen candidate and its constraints.

The AI Research OS video reinforces the current architecture: source intake and memory discipline are the substrate, while RALPH's extra value is decision promotion. Loops should create durable memory only when they produce source-grade evidence, reusable synthesis, a changed unknown/candidate, or a decision.

The wallet-shadowing transcripts add the most important M1 correction so far: do not treat Trump-person event wallets as copy-trading alpha. They are useful as event/risk radar, but the copyable strategy question belongs in broader wallet-shadowing archetype research. TRUMP coin, MELANIA coin, and token treasury clusters are noise for Tomas's intended thesis.

Tomas's latency-axis correction sharpens the strategy question: the first filter is not coin, venue, or famous wallet. The first filter is whether the edge is slow enough to survive Tomas's observation and execution delay. BTC/ETH directional perps are useful data rails, but fast CEX-led price discovery makes them weak default shadow targets. Slower archetypes such as structural funding/basis positions, mid-cap accumulation, and aggregate cohort flow may be more shadowable. RALPH should validate any candidate through frozen-cohort forward paper-trading with latency, slippage, beta decomposition, and multiple-testing controls.

The patient-retail strategy map turns this into a practical strategy selector. The strongest near-term branches are smart-money accumulation as cohort flow and funding/basis as a structural baseline. These branches are not proven, but they match Tomas's preference for patient strategies that can wait days or weeks rather than compete on speed.

The tool-first pivot corrects RALPH's implementation instinct. RALPH should not build a custom bot, scanner, data warehouse, grid tool, copy platform, or paper-trade harness until existing tools have been inspected. The likely custom work is much smaller: a signal layer, an adapter, source-backed decision discipline, and Tomas-specific validation.

> Updated synthesis: wallet shadowing is a good first project because it builds reusable trading-research infrastructure, not because copying famous wallets is easy.
