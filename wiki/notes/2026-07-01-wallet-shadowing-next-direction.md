# Wallet Shadowing Next Direction

## Blunt Direction

Stop the model ping-pong. The useful design has converged.

Do not continue hunting Trump-branded coin or family-token wallets. Tomas meant Trump as the president/person and his market-moving public statements, not TRUMP/MELANIA coins.

Do not continue hunting "Trump wallets" as the main strategy either. The useful part is presidential event risk: wallets that position before or around statements, policy posts, tariff announcements, crypto-reserve mentions, geopolitical comments, or other Trump-person market shocks. That path can produce radar material, but not a copy-trading edge by itself.

The next RALPH direction should be:

> Wallet-shadowing archetype research, with Hyperliquid as the first practical data-feasibility branch and Trump-the-person event radar as a separate overlay.

The core axis is now shadowability by latency. BTC/ETH directional perps are not automatically the target; they are just the easiest first data rail to inspect.

After the patient-retail strategy map, the preferred M1 framing is even sharper:

> Tomas wants patient, low-latency-dependence strategies. RALPH should prioritize smart-money cohort accumulation and funding/basis structural baseline over fast directional copying.

After the tool-first pivot, implementation scope is narrower:

> Use existing engines and products first. Build only the missing signal, adapter, or validation decision layer.

After Tomas clarified copy-trading scope, RALPH should split copy-trading into two categories:

- fast perp mirroring: default reject/radar/prior-art because it violates the no-latency constraint;
- slow mid-cap accumulator following: valid patient-retail candidate if cohort-based and round-trip tested.

Source: [[wiki/sources/slow-copy-trading-distinction-2026-07-01]].

The slow accumulator signal source appears to be Nansen/Arkham/Dune, not Copin-style perp copy trading. See [[wiki/comparisons/slow-accumulator-tool-fit-map]].

The "be the house" idea adds another branch: [[wiki/concepts/liquidation-map-liquidity-provision]]. This is not wallet copying; it is passive liquidity provision around forced-flow clusters. It must be treated as negative-skew until replay proves otherwise.

## M1 Replacement Priority

The previous M1 top loop `event-triggered-wallet-shadow-falsification` should be reframed as:

1. `wallet-shadowing-prior-art-scan`
2. `wallet-shadowing-archetype-shadowability-map`
3. `hyperliquid-data-feasibility-spike`
4. `wallet-shadowing-falsification`
5. `forward-paper-trade-mvp-spec`

## MVP Shape

Do not build a trading bot. Build a no-key research and paper-trade system:

1. Pick an archetype branch: structural/funding, mid-cap accumulation, aggregate flow, or Hyperliquid directional perps.
2. Import or discover 100-500 candidate wallets/cohorts from an activity-defined universe.
3. Fetch historical fills/position changes or flow data.
4. Compute screening metrics.
5. Select a frozen cohort.
6. Simulate forward copy/flow-following with latency/cost scenarios.
7. Report capture ratio, drawdown, expectancy, beta-adjusted residual PnL, and outlier dependence.

For patient-retail branches, stretch the latency axis from seconds/minutes to hours/days and measure full round-trip capture, not entry-only capture.

## Data/Tool Priority

1. Hyperliquid public API and ecosystem tools for perp branch feasibility.
2. Copin / HyperX / HyperDash / Hypurrscan / ASXN as prior art and reference implementations.
3. Dune for SQL screening if coverage is useful.
4. Arkham/Nansen for labels, cohort discovery, and mid-cap accumulation/flow research, not truth.
5. Tenderly later for execution simulation, not discovery.
6. EigenPhi later only for MEV strategy family.
7. Messari later for fundamental/narrative research, not wallet shadowing.

## Promotion Rules

Promote to experiment only if:

- prior art does not already answer the exact question;
- data is available without keys or paid infra;
- candidate universe can be defined by activity, not leaderboard;
- paper-trade can run without live capital;
- false positives from multiple testing are handled.

## Current Recommendation

Run manual A1 loops first. No recurring loop yet.

The first useful loop is not "build scanner immediately." It is:

> Prior-art/tool scan: is Copin/HyperX/Nansen/Dune already enough to answer the first question, and what does RALPH still need to build itself?

After Tomas's latency-axis correction, the more precise next question is:

> Which wallet-shadowing archetype has an edge slow enough to survive Tomas's latency?

After ingesting the patient-retail map, the first concrete branch should be one of:

- `smart-money-cohort-discovery-layer`;
- `funding-basis-baseline-monitor`.
- `liquidation-map-build-vs-buy`.

Do not build both simultaneously unless a later decision explicitly expands scope.

Before either branch, run `existing-tool-fit-map`.

For the slow accumulator branch, the next concrete question is:

> Can Nansen plus Arkham plus Dune produce a slow mid-cap accumulator cohort that can be frozen and forward-tested?
