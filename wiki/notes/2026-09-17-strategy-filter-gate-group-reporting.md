# Strategy Filter Gate Group Reporting

Bounded work item: `validation.strategy-filter-gate-group-reporting`.

## Question

Yesterday's PSR diagnostic overlap audit concluded that adding another hard probability threshold would create false precision. The next useful harness improvement was reporting clarity: make grouped gate pass counts reproducible in the filter report instead of relying on one-off scripts.

## Implementation

Added `gateGroupDiagnostics` to `experiments/strategy-destruction-filter/results/filter-report.json` and a matching `Gate Group Diagnostics` section to `filter-report.md`.

The grouped diagnostics now report:

- `headline_pass`: minimum sample, expectancy, profit factor, drawdown, and worst-slice gates.
- `deflated_sharpe_pass`: configured approximate multiple-testing deflated-Sharpe floor.
- `oos_pass`: chronological out-of-sample sample and expectancy gates.
- `baseline_pass`: full-sample and out-of-sample lift versus the time-matched alternating-direction baseline.
- `walk_forward_pass`: equal-trade-count walk-forward positive-fold and diagnostic OOS-fold checks.
- `psr_diagnostic_band`: diagnostic-only PSR-style bands at `<0.95`, `>=0.95`, `>=0.975`, and `>=0.99`.
- `effective_shape_pass`: raw survivors collapsed into effective survivor shapes.

The verifier now requires these diagnostics to exist, checks pass-count consistency, checks the PSR band section, and verifies that the effective-shape diagnostic matches the report totals.
