# RALPH Operating Thesis Voice Note

Raw source: [[raw/ralph-operating-thesis-voice-note-2026-07-01]]

## Why This Source Matters

This is the clearest source for what Tomas wants RALPH to become: not a static wiki, but a self-improving second brain that runs loops, researches strategy/system design, learns from failure, and eventually helps assemble a realistic trading bot system.

## Key Claims

- RALPH should be the AI Research OS / second brain, not merely a folder structure.
- Trading bot design cannot be chosen before strategy discovery; the strategy is still unknown.
- Current intuition points toward wallet-shadowing plus high-volatility / large-move event triggers.
- Budget is a hard constraint: roughly $100/month preferred, $100-200/month maximum for infra at this stage.
- Solana speed competition is likely the wrong battlefield.
- RALPH should research EVM/CEX/backtesting/simulation alternatives and trading bot system architectures.
- RALPH should run recurring research loops in the background, with retries and failure learning, while keeping Tomas in the loop where human action is needed.
- RALPH should turn repeated successful/failing procedures into reusable skills or durable instructions.
- GitHub research, Twitter/X research, framework research, strategy research, simulation research, and market watcher inputs should feed the same decision system.

## RALPH Implications

- Add an operating thesis that explicitly centers strategy discovery before system design.
- Add a strategy research loop, repo/framework discovery loop, and market volatility watch loop.
- Add milestones so RALPH can make progress without waiting for Tomas to micromanage every next step.
- Add a skill creation policy, but keep generated skills as proposals until explicitly applied.
- A2 automation can be designed now, but it must stay read-only and no-trading.
