Definitions
- The six: BTCUSDT, ETHUSDT, SOLUSDT, XRPUSDT, DOGEUSDT, HYPEUSDT. Seal: 2025-10-17T00:00:00Z. Window W = [2025-05-01T00:00:00Z, seal).
- t = calc_time floored to the full hour (settlement hour, in ms); h = the integer value of the funding_interval_hours token (I2).
- Allowed months: 2025-04 to 2025-10. Month status, one per allowed month of every symbol that has at least one frozen key: verified_nonempty, verified_empty (verified, no pre-seal row), excluded:<check>, not_verified, not_listed.
- Segment: per symbol, the retained pre-seal rows of a maximal sequence of consecutive allowed months that are all verified_nonempty, in month order and source order within a file. Any other month status breaks the sequence. Segment ids: 1, 2, ... per symbol in time order. Rows of different segments are never paired.
- Pair (p, r): two consecutive rows of one segment. Eligible: r.t in W (April rows serve only as p).
- Era of a pair, by r.t, half-open: era1 before 2025-05-02T08:00:00Z; era2 [2025-05-02T08:00:00Z, 2025-09-01T00:00:00Z); era3 [2025-09-01T00:00:00Z, seal). cross_era: p.t lies in an earlier era. tree: symbol TREEUSDT and r.t inside the closed S3 window (p may lie outside it).

S. Sample (a rule, no discretion)
S1 Symbols and keys: list the immediate symbol prefixes under data/futures/um/monthly/fundingRate/ in the public S3 listing of data.binance.vision with delimiter "/", all pages until the listing is not truncated. Drop exactly the six before listing anything below a symbol prefix; no object key of the six is listed, downloaded or read (receiving their prefix names is not listing their files). Other contracts of the same coins (e.g. BTCUSDC) are included. No status, currency or liquidity filter. A symbol prefix containing a comma, double quote, CR, LF, "#", "@", ":", ";", "+", a control character, a whitespace character (any of the 25 code points that \s matches in JavaScript on Node 24.22.0: U+0009 to U+000D, U+0020, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF) or invalid UTF-8 leaves the freeze unresolved. Then list every remaining symbol prefix, all pages. A frozen key is the canonical object <symbol>/<symbol>-fundingRate-YYYY-MM.zip under that root for an allowed month. Its sidecar is the frozen key followed by .CHECKSUM: a sidecar is not a key, is fetched only for its frozen key (I1) whether or not the listing shows it, and is not counted as another object. Any other object name (other months, other sidecars, non-canonical names) is counted in O6 and never fetched. Keys are used byte for byte as the listing returns them after XML entity decoding, never normalized. A download URL is https://data.binance.vision/data/futures/um/monthly/fundingRate/ followed by the key (plus .CHECKSUM for a sidecar), with every byte outside A-Z, a-z, 0-9, "-", ".", "_", "~" and "/" percent-encoded as %XX (uppercase hex, UTF-8 bytes). The exact listing endpoint, its query encoding and this download encoding are fixed and tested on real keys in the run document (R7). A repeated page, cursor or key, or pagination that does not end, leaves the freeze unresolved (F1). The symbol list (symbol names without root or trailing slash) and the key list (root-relative frozen keys) are frozen as UTF-8, one item per LF-terminated line, sorted by unsigned bytes, written as O8 and hashed, before any CSV is read. A symbol absent from the listing is outside the archive-available universe, not evidence that it had no episode.
S2 Files: every frozen key. Rows are routed by I2. April rows are predecessors and context only.
S3 Control: TREEUSDT is also reported as a fixed window, every settlement from 2025-08-31T08:00:00Z to 2025-09-01T04:00:00Z inclusive, because the 2025-09-01 announcement gives a conditional schedule for it (contract section 2). It is a control, not a required event and not a P0 reason. Status, first match: unavailable if no retained TREEUSDT row lies in the window (also when TREEUSDT has no frozen key); available if TREEUSDT 2025-08 and 2025-09 are both verified_nonempty and one segment contains both a retained row at or before 2025-08-31T08:00:00Z and a retained row at or after 2025-09-01T04:00:00Z; else partial. Available does not certify that no settlement inside the window is missing. Rates are never used to decide whether the condition was met; an unavailable window is a coverage result and is never replaced by another symbol.

I. Integrity
I1 Per frozen key, check in this order and record only the first failure; check names are the words in parentheses. (missing_checksum) the sidecar is available; zip availability; (checksum) the sidecar bytes are exactly 64 lowercase hex digits, two spaces, the zip basename and one LF, nothing else (the form parseChecksum in experiments/strategy-destruction-filter/src/vision-source.mjs at c33f9c7 accepts); (hash) the sha256 of the fetched zip bytes equals those 64 digits; (archive) the bytes end with a ZIP end record, single disk, no zip64, and the central directory sits directly before the end record and is well formed; (member) exactly one entry, named as the zip basename with .zip replaced by .csv, general-purpose flags 0, compression method 8 (deflate), a local header that agrees with the central directory in flags, method and name, and member data that ends before the central directory; (crc) the member inflates, its length equals the declared size and its CRC32 equals the declared CRC; then header and rows (I2). Archive, member and crc accept the variant readZipMember in the same file at c33f9c7 accepts. Availability: a sidecar or zip that fails after the permitted retry (F2) is not_verified after the first pass, also when its absence is established by HTTP 404; in the completion pass, a sidecar established absent (HTTP 404) again is final excluded:missing_checksum, and any other availability failure is final not_verified. Failures from checksum on are excluded:<check> and are never retried. No row of an excluded or not-verified file enters any output, and bytes of a fetch that did not complete are never written to any output. Hash, CRC and member checks process whole archives including sealed bytes; this is an opaque integrity operation and authorizes no semantic read or export of sealed rows. Use only the sidecar and zip bytes fetched for that key in this run; never refresh a source between E1 and E2.
I2 Grammar. The member is split at LF. CR and BOM are not normalized. If the member ends with LF, the empty string after the final LF is not a line; if the bytes after the final LF are not empty, they are the last line and it is unterminated. Line 1 is the header if it equals exactly calc_time,funding_interval_hours,last_funding_rate; otherwise it is a data row. Data rows are checked one at a time in source order (never sorted), all checks of a row before the next row; the first failing check of the first failing row excludes the file as excluded:<check>, and no token value or row number is reported. Per row, in this order: (routing) the first comma-delimited token is exactly 13 ASCII digits (an empty line fails here). A row with calc_time at or after the seal: in a file of month 2025-10 it is dropped, with no further check, count or statistic; in a file of months 2025-04 to 2025-09 it lies outside the file month by construction and excludes the file as excluded:month, with no other field of that row read. A pre-seal row: (framing) it is not the unterminated last line; (fields) exactly 3 comma-separated fields; (month) calc_time inside the file month; (order) calc_time strictly greater than the previous pre-seal calc_time; (hour) not in the settlement hour of an earlier pre-seal row; (interval) the interval token matches [1-9][0-9]* and is at most 9007199254740991. Outputs use the canonical decimal spelling of h. The third field must be present; its value is never decoded, validated or reported.

D. Detection (cadence runs are label-independent; isolated candidates use label 1)
D1 Cadence run: within one segment, a maximal sequence of at least two rows whose every step r.t - p.t is exactly 1 h. Run endpoints are observed cadence, not a claimed administrative entry or exit.
D2 Retained runs: every run with at least one row in W, including runs that began in April. Entry status, first match: left_censored_segment if the first row has no predecessor in its segment; left_censored_window if the first row lies before W; else observed. Exit status, first match: observed if the last row has a successor in its segment; right_censored_seal if the last month of its segment is 2025-10; else right_censored_segment. right_censored_seal means the observation is truncated at the seal, not that hourly funding continued to it. The termination cause of an unobserved exit is unknown and never inferred (delisting only with dated independent documentation).
D3 Isolated candidates: every row in W with h = 1 that is in no retained run, without any distance exclusion.
D4 Limit: a regime with neither a 1 h step nor an h = 1 row cannot be identified from these fields; this gate makes no claim about it.
D5 Roles and ids: run ids <symbol>#<n>, n = 1, 2, ... per symbol in order of the run's first retained row; isolated candidate ids <symbol>@<calc_time>. For a retained run with rows a1..an: entry_outer = (predecessor of a1, a1); entry_inner = (a1, a2); exit_inner = (a(n-1), an); exit_outer = (an, successor of an); interior = every other pair inside the run. For an isolated candidate x: isolated_in = (predecessor of x, x), isolated_out = (x, successor of x). A pair can carry roles for several ids (e.g. exit_outer of one run and entry_outer of the next). Encoding (O5 roles field): semicolon-separated <id>:<roles>, run ids by numeric n first, then isolated ids by calc_time; <roles> joins the distinct roles of one id with "+" in the order entry_outer, entry_inner, interior, exit_inner, exit_outer, isolated_in, isolated_out. An empty field means role none.

P. Outcome policy (fixed now)
Hourly-related pair: eligible pair with a non-empty roles field. Boundary pair: roles contain entry_outer or exit_outer. Observed boundary: entry_outer of a run whose entry status is observed, or exit_outer of a run whose exit status is observed.
P0, P3, P1, P2 are evaluated in this order; the first that matches decides. Documented regimes and directions, the applicable document and its scope, any documented discriminator, an amendment rule and the adequacy of its synthetic validation are judgments made by Claude from the contract sources and approved by Tomas (question tool); the script never decides or outputs them.
P0 Inconclusive: the freeze is unresolved or has no key; after the completion pass any frozen key is excluded or not_verified (zero tolerance, Tomas 2026-10-29); any month 2025-04 to 2025-09 of a symbol with frozen keys is verified_empty; the scheduleClass file sha, a module hash or the Node version differs; E2 finds any difference; an O10 row has hourly_related true. No amendment and no protected invocation. Collection may finish under F2/F3; verified observations and every stop are still reported, but a subset is never promoted to a census result. New decision by Tomas, who may authorize a separately defined reduced claim.
P3 Coverage: era2 or era3 has no hourly-related pair, or no retained run has an observed boundary. Report entry_outer, entry_inner, exit_inner and exit_outer evidence separately by era, with zero and censored cells explicit (O9, O6). New decision by Tomas; no amendment and no protected invocation. A limited statement about observed pairs is allowed. In every outcome, a direction or documented regime absent from the evidence is outside any compatibility claim, and an amendment that needs absent evidence requires a new decision by Tomas and cannot authorize the protected invocation.
P1 Every hourly-related pair passes (regular, interval_change, bridge): report compatibility of the code with the observed hourly-related pairs only, with the coverage matrix, every distinct label pattern (an O9 row with a role other than none and pairs above 0) and the count of role-none stops, which stay unexplained and limit the statement. This proves no unique label convention, no full coverage and no cause of the HYPE 2026-06 failure. New decision by Tomas between (b) and (c) of 2026-10-29.
P2 Some hourly-related pair stops: report every stop by class, symbol, episode, role and era. Amendment 2 (Claude Code, branch f1/a4-funding) may be proposed only as one generic rule that documented rule versions and these pre-seal labels explain for every affected case, without symbol-specific exceptions and without weakening unchanged-interval gap detection; where labels differ between eras, only an explicitly date-scoped documented rule. The applicable document and its effective scope are recorded; unknown applicability means no amendment. The rule may cover only directions and regimes with observed evidence, and it must leave the class of every role-none pair unchanged. If stops differ between episodes of one documented regime with no documented discriminator, if no such rule exists, or if it would change a role-none class: new decision by Tomas, no amendment. Before the protected invocation, the amendment is validated against every retained pre-seal pair and against synthetic positive and negative fixtures, and the amendment commit, dependency hashes, fixture results, exact command and output schema are frozen and approved by Tomas.
P4 Rule versions after 2025-10-16 (for example the 2026-01-02 settlement-frequency announcement) are not covered: no result here validates them or post-seal label serialization, and a passing protected invocation is not evidence that the pre-seal sample explains the failure; every other open gate still blocks holdout evaluation.
P5 Stops on pairs with role none (for example ordinary missing settlements) are reported in full in O5, with their count in O6 and the O5 hash in O11. They never select P1 or P2, never authorize an amendment, and are not diagnosed here as an hourly event or as an ordinary missing settlement; an amendment must not change their class; a P1 or P2 statement names their count and says they are unexplained.

F. Failure policy for the run
F1 A listing page fails after one retry, or the freeze is unresolved: stop (the sample cannot be frozen). The run then writes only O6 (the items reached), O13 (P0 freeze_unresolved) and O11.
F2 One source object (zip or CHECKSUM) fails after one retry: the file is not_verified and breaks its segment; the run continues. After the first pass over all frozen keys, exactly one completion pass re-attempts only the not_verified keys, with the same frozen list, checks and retry rule. Excluded keys are never re-attempted, and the sample never changes. Statuses after the completion pass are final; a sidecar established absent (HTTP 404) in the completion pass is final excluded:missing_checksum (I1).
F3 Exclusions under I1 and I2 are results, not stop reasons, and are never retried to change the sample.
F4 Precedence: F1 to F3 replace any generic acquisition retry; F6 aborts are terminal and do not use F5; P6 overrides every retry clause. Otherwise R1 to R7 and the exact failure rule of the run document apply.
F5 Implementation errors, a wrong pinned identity, a privacy or scope violation or an incomplete output write invalidate the run; no result is published from partial outputs, and a failed output write leaves only an invalid-run marker. One fix and one rerun are allowed, within this spec, and only before any protected invocation.
F6 Resources: the scan runs as a transient unit with MemoryMax=512M, MemorySwapMax=0 and CPUQuota=50%, within the R6 ceiling (at most 1 GiB, 50 % CPU), and starts only when MemAvailable is at least 600 MiB. It streams one file at a time. Keys are counted as monthly zip objects, excluding .CHECKSUM sidecars; more than 10,000 frozen zip keys stops the run before any source object is fetched. A byte counter covers every received HTTP body byte (listing, zip and .CHECKSUM requests, failed attempts, retries and the completion pass); the run aborts when it would exceed 1,073,741,824 bytes. The run document freezes exact decompression, line and output-space bounds and tests its resource checks; hitting any bound is a resource abort, not an exclusion. A resource abort, an OOM, an output-space failure or a preflight rejection gives no valid result and is never restarted automatically or given higher limits.
