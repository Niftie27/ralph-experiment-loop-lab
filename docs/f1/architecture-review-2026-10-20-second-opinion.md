## F1–F12

- **F1 — partly.** H:119 selects existing objects, H:125 serializes the whole window, H:147 creates the per-bar frozen copies; it does not build a separate initial object set, although callers already supply objects, and E:350–351 selects/freezes on every run. Prefer bounded columnar reads, but a bespoke binary ABI needs a specified header length, endian encoding, schema evolution, units and immutable-reader contract; decimal parsing alone cannot prove identical complete files, and monthly JSON need not imply loading four years at once.
- **F2 — partly.** Period splits are justified by H:17–28 and whole-file hashing is real (H:148; E:359), but manifest growth does NOT currently change trial identity/deduplication (H:72–75,91–98); it changes provenance. Use immutable dependency hashes including BTC context, funding and transformation closure, while preserving a separately versioned trial key and legacy append-only history (I60).
- **F3 — partly.** `cachedSeries` has no holdout authorization (H:150–160); the queue's research restriction and engine guard exist (Q:14–17; W:7; E:349), but H:77–84 only checks a flag and a matching research identity, not a successful survivor or single use. A period label alone is not a seal: validate timestamp bounds and all read paths, and separate privileged ingestion from research access; a reader refusal cannot physically hide a mixed-month ZIP.
- **F4 — partly.** Keep Node for the present harness, but existing code volume and unverified rewrite estimates do not establish the best live runtime; shared semantics and state matter more than a language label (spec:67,186–187). Do not quietly repurpose approved D6 from live parity into an allegedly independent fill-realism check: two engines on the same 1m bars cannot establish true intrabar execution (spec:63,169; decisions:32).
- **F5 — partly.** E:355–361 stores exactly four metrics and no return series; all 400 inspected rows have that metric-key set, so storing trades and daily equity artifacts is necessary. Changed engine hashes do not make old replay inherently impossible if the old source and inputs survive; exact recoverability is not verified, and one cluster per missing historical trial is a conservative accounting choice, not proof that the complete effective-N/DSR procedure is calibrated (H:91–98; Q:113–134).
- **F6 — partly.** A pre-authorized, fixed data-quality comparison is useful, but D004 documents file availability rather than complete exchange-time coverage (catalog:248–265), and live feature ingestion excludes REST backfill (tools/collector/binance_live.py:611,663). Matching OHLCV/bought volume cannot certify profile, VWAP or as-observed latency parity: declare those inputs absent or separately derived, pre-fix dates/metrics/tolerances, and expose no prices, signals or returns to strategy selection.
- **F7 — partly.** Per-style costs are needed, but “limit means maker” is not demonstrated by this implementation: E:288–302 only models close/next-open entries and symmetric costs, not resting/post-only enforcement or separate exit liquidity. Require explicit passive-entry eligibility, taker stops, partial/nonfills and adverse selection; keep the approved taker scenario as stress, and enforce an aggregate job budget rather than assuming 512 MiB per process protects a 1 GiB cgroup.
- **F8 — partly.** Host-agnostic jobs and monthly ingestion are sensible, but the historical memory figures are not current capacity: this inspection found 737 MiB available, below I56's 1.5 GiB floor (readings below). Raising a WSL limit is not justified without physical-host headroom, and chunking must also bound parsing, aggregation and concurrent parent/worker memory.
- **F9 — partly.** Keep spot deferred; however, a new market is not necessarily just a mapping row because input capability validation and provider behavior already differ (H:37–51; Q:19–36). Spot/index additions require explicit timestamp units, contract/volume semantics, gaps and point-in-time revision policy; current external provider coverage and prices are not verified here.
- **F10 — disagree.** ZIPs plus code are insufficient backup policy for the proposed trial return/trade artifacts, preregistrations, dependency versions and source CHECKSUM history; Git tracking of manifests is not a verified restore. Require a retention manifest and a clean-environment restore/hash test; ~0.2 GB is approximately the uncompressed numeric payload for five years × ten float64 columns, not a measured ZIP-plus-snapshot-plus-results storage budget.
- **F11 — partly.** Agree on tracked authority and the checksum gap: A:19–40 reads cached CSV or downloads/unzips/writes it without CHECKSUM verification, and A:43–56 only handles ZIP framing/compression. Do not simply switch alert-edge to a kline loader: A:154–174 consumes trades and bookDepth, so share verified transport with typed parsers or mark legacy, without touching R1 runtimes; local CLAUDE.md contents and relay timing remain not verified.
- **F12 — partly.** Both verdict functions emit only `rejected`/`survived_research_gate`, including sample failures (E:615–668), and W:28 collapses everything else to reject, so add `inconclusive` for insufficient evidence without letting it override a separately established failure. Judge pre-registered family selection procedures, retain every variant/trial and failure reason, permit inconclusive retests only under a locked new-data rule, and add gross/net cost attribution (E:328–338); a taker-cost failure is not automatically a wrong kill without an executable passive-fill model, while the planted-edge test is already required (spec:183), and hand-picked reject revival stays forbidden.

## Memory numbers: interpretation, not rerun

No memory benchmark was run. The allocation paths support the danger, not the exact 1,371/1,916 MiB peaks or 6.3/9.6 s timings: caller-owned objects, two selection arrays (E:350; H:119), full JSON, cached-file verification buffers (H:131–132), and frozen copies can overlap, with GC/runtime-dependent peaks. Seven float64 columns × 2,102,400 rows = 117,734,400 bytes before a header; this validates arithmetic only, not the reported gzip size or RSS. Ten columns across six full histories exceed 1 GiB even before features and trades. The spec already allows typed arrays OR selective 1m loading (spec:132); “no rebuild” is conditional on bounded end-to-end evaluation, not merely a new writer.

## Missing rebuild risks, ranked (max five)

1. **Equity/accounting contract.** Daily returns require initial capital, sizing, concurrent-position limits, mark-to-market, fees and funding timing, zero-exposure days and missing-day rules. E:402–420 independently simulates every signal, while E:473 uses trade netR; summing exits by date is not a portfolio equity model. Freeze this before artifact schema and DSR.
2. **Executable identity and crash consistency.** E:360 hashes only engine.mjs, not imported rules, caller signalGate (W:17–26), configuration/schema or dependency closure; H:138–144 read-modify-writes a manifest and E:355 appends a result separately. Future concurrent/restarted jobs need atomic publication, idempotent trial reservations and recovery rules before a timer, not just append-only JSONL.
3. **Sparse multi-timeframe/time-availability contract.** Q:23–26 requires exact contiguous coverage, contradicting simply passing sparse new files through unchanged. Define incomplete aggregates, UTC week alignment, warmup and event-time versus availability-time joins; catalog:123 has no bar receive timestamp, so finalized history cannot prove live availability.
4. **Calibration/power and adaptive trial accounting.** Raw trial identity must include market and procedure without counting technical repeats; H:91–98 and Q:121–125 currently omit instrument. Null tests alone can reward a reject-everything funnel: specify planted-edge power by frequency/cost/coverage, uncertainty on false-pass rate, and how inconclusive/family decisions affect future trial budgets before F1b.
5. **Mutable buffers and storage lifecycle.** The proposed typed-array reader needs ownership/copy rules so one strategy cannot alter another's inputs after verification; define durable raw/derived/result retention and restore tests before adopting a private binary ABI. One-time hashes without immutable bytes do not establish reproducibility.

## My picks for the five decisions

1. **Columnar binary, conditional:** Node built-ins fit the current constraint; specify and test a small versioned ABI and bounded reader before committing full history. Keep standardized formats as an alternative if dependencies are later allowed; reject the unproven half-day estimate.
2. **Node for F1 blocks; live choice provisional until before F1d:** use an actual closed-bar state/parity fixture and execution requirements to decide. D6 changes require an explicit new decision; line counts are not that evidence.
3. **Node statistics with pinned independent Python fixtures:** include adversarial/degenerate and correlated-return cases, tolerances, null campaigns and planted edges. Fixture agreement alone is not model validation; no Python install authorized here.
4. **Yes, conditional on explicit sealed-data authorization:** an outcome-blind quality checker with a locked input contract and aggregate mismatch report; do not run it in this task. Separate historical reconciliation from as-observed live fidelity.
5. **Spot only for a pre-registered comparison:** preserves scope and trial budget; no download now.
